# Design

## Context

动机及用户确认的范围见 [proposal.md](proposal.md)。当前分支为 `codex/banyan-omega-topology`。实现及23项验收任务已完成；实测结果与复现说明见 [PRUNED_BANYAN.md](../../../docs/PRUNED_BANYAN.md)。下文保留设计决策及实施前的风险判断。

已检查的工程基础：

- `network.py` 分派标准 Beneš 与 `as_network.py`；两者都先补全置换，再求解，并在验证时要求 `rearrangeable=True`。这一契约不能直接用于有阻塞、含内部终端的网络。
- `as_layout.py` 已有单带、左右GSG器件、共享地和两排pad，但假定全部内部轨道都有公开I/O，所有边界都是完整置换；其I/O映射使用 `.index(row)`，不能承接裁剪图。
- `as_geometry.py` / `interstage.py` 已有连续斜线、可复用crossing和逐路径piece记录；可保留活跃轨迹、删掉无用分支，但不能直接引用完整128路shuffle单元后只修改计数。
- `as_channel.py`、`ground_column`及现有GDS金属提取可复用。共享地需要重新考虑稀疏列、终端和实际光学障碍。
- `geometry.py` 的终端明确为 `placeholder=True, reflectionless=False`；可复用几何接口，不能宣称已做低反射设计或验证。
- `tests/test_as_benes.py` 已覆盖100路全单连接、非2幂规模、GDS和故障；新模式要增加成功/阻塞分类，不修改这些原有无阻塞用例。

现有物理基线为 `examples/benes/exact100-balanced/regular.json` 与 `regular-choice.json`，摘要在 `docs/assets/final-layout-summary.json`：596 MZI、4,522 crossing、604 pad、2,528 via、20.252711×4.555112 mm、92.253366908632 mm²。

探索中的400-MZI裁剪图已用前后可达集合和独立10,000条选定路径并集两种方式核算；2,433为原轨道相对顺序的逆序对计数。没有生成该候选的GDS，不能引用这些结果作为物理验收证据。

## Goals / Non-Goals

**Goals:**

- 用同一个显式裁剪端口图驱动逻辑、布局及导出，并让验证器独立重建连接，避免母网地址与物理保留数量混淆。
- 完整保留已选100×100连接关系、至少一种满载状态，明确请求失败语义和暗输入假设。
- 将图计数转换成可验证的光电几何，以真实全片面积和全片crossing判断收益。
- 参数化拓扑N≥2，覆盖小规模物理验收与100路交付；大规模只做拓扑统计，不借此宣称大规模物理已通过。

**Non-Goals:**

- 不实现GSEN、Clements、多平面、分时调度、无阻塞扩展或新的工艺层。
- 不采用两端直接取前100口的350-MZI裁剪方案：它虽单对可达，但最大同时连接数仅79，与选定的满载参考能力不同。
- 不继续全局搜索输入/输出子集，不更改公开端口顺序来隐藏额外交叉，不实现用户自定义裁剪集合。
- 不校准终端反射、MZI损耗/串扰、RF阻抗或工艺DRC，不将终端占位几何当作吸收器件认证。

## Decisions

### 1. 新模式与母网地址空间

配置增加 `topology: "pruned-banyan"`，`active_ports=N`，`internal_ports=P=2^ceil(log2 N)`。这里P明确表示母网轨道编号空间，不表示每个级间实际布置P条波导。只接受该默认P；N≥2且必须为整数。旧模式的默认值及哈希不变，新模式字段只在新模式序列化中生效。

逻辑实现建议置于 `banyan_network.py`，由 `Network` 分派；布局/工作流/验证使用专用入口，如 `banyan_layout.py`、`banyan_workflow.py`、`banyan_verify.py`，再按必要程度复用或抽取纯几何与电学辅助。避免让AS验证器接受不完整置换而削弱历史验收。

导出同时包含 `active_ports`、`parent_ports`、逐级有效边、保留开关、公开端口映射和终端绑定；开关ID包含母网stage/row，物理压缩行号另存。类似“删除后重新按行编号”的方案会破坏稳定控制ID，故不采用。

### 2. 精确定义选定的400-MZI构造

母网为当前标准Beneš前半部分对应的递归Banyan：P条轨道、k=log2 P级，每级相邻两轨组成2×2开关。边界s（0≤s<k−1）的局部块大小为 `m=P>>s`，块内映射为

```
split_m(i) = floor(i/2) + (i mod 2)*(m/2)
```

按各块基址拼成全局置换。此定义固定方向与轨道约定，不与每级重复全宽shuffle的Omega排布混用。

公开输入a对应母网输入a（0≤a<N）。令B(a)为母网全bar状态的输出轨道，则保留输出集合 `O=sorted({B(a): 0<=a<N})`，公开输出j对应O[j]。满载参考为 `a -> index_O(B(a))`；这通常不是公开恒等置换。

对母网做前向可达与从O反向可达分析，保留同时位于有效输入到有效输出路径上的器件及边。由于母网每对只有一条路径，这正是全部N²条所需路径的并集。生成器不必枚举N²路径；验证器使用独立路径计数/枚举核对，不能共享裁剪判定作为唯一证据。

100路固定验收清单：

| 项目 | 数值 |
|---|---|
| P / k | 128 / 7 |
| 每列MZI | 50, 50, 52, 56, 64, 64, 64 |
| 总MZI | 400 |
| 级间有效边 | 100, 100, 104, 112, 128, 128 |
| 保留器件的有效输入/输出度 | 344个(2,2)、28个(1,2)、28个(2,1) |
| 片内终端 | 28个未用输入端 + 28个未用输出端 |
| 原相对轨道顺序的级间交叉 | 1225, 600, 312, 168, 96, 32；总计2433 |
| 10,000个有效输入输出对 | 每对唯一，均经过7个MZI |

小规模如果出现(1,1)保留器件，先保留该MZI及未用端口终端，保持统一层级与k级定义；100路参考没有这类器件。本次不引入不同的删减开关优化。

标准Banyan的背景参考：[Switching textbook, recursive Banyan construction](https://www.ee.nthu.edu.tw/cschang/switchbook.pdf)。400、2433及本表其他数值是上述具体裁剪构造的项目计算结果，不声称文献给出了相同数值或全局最小值。

### 3. 唯一路径求解与失败行为

为每条实际请求计算唯一路径，将每个经过开关的 `state=input_pin XOR output_pin` 合并到约束表，同时维护有向链路占用者。状态矛盾或链路争用时报告 `blocked`、请求对、stage、switch/edge；重复公开端口及非法编号属于输入错误，与内部阻塞区分。按排序后的请求处理，保证诊断和结果确定。

未约束开关默认bar，成功结果覆盖所有保留开关；记录 `rearrangeable=False`、`blocking=True`、实际请求和暗输入。不能调用旧的“任意补全未请求输入/输出”逻辑。未请求输入在这些状态下可能到达其他公开输出或终端，若报告其去向，必须实际走图而不是捏造完整公开置换。

验证器依据边图和状态追踪请求，遇到终端、错端口、重复占用或非法状态即失败。对成功的全部状态，bar/cross在每个2×2器件内部仍是合法双射，但裁剪网络不保证每个状态都把100个公开输入送往100个公开输出。

CLI显式增加 `pruned-banyan` 选择及满载参考连接模式（建议名称 `reference`）。通过区分连接参数省略与显式 `identity`，仅为新模式把省略行为映射到参考置换；旧模式保持identity默认。显式identity/reverse一律按用户请求求解，阻塞则拒绝。空请求保留完整默认状态并标明所有输入暗态。

输出先在隔离临时目录求解/生成/验证，再发布完整包。失败不能覆盖成功包或将旧settings当作本次结果；CLI非零退出，错误明确指出目标目录旧包是否仍保留，失败诊断独立记录。此策略避免现有 `generate` 先创建输出目录再求解时留下含混状态。

### 4. 稀疏连续光学块与100口适配

初始布局保留母网轨道的相对顺序，移除不需要的器件和分支；这使2433计数与保留曲线有直接对应，也避免一开始使用任意行重排导致现有连续模板失效。

扩展连续shuffle的“活动轨迹集合”能力，缓存键包括块大小、方向、活动输入/输出轨迹及间距。逐个原crossing判断两条轨迹是否保留：

- 两条都保留：放置一个真实crossing，两条路径各记录其贯通关系。
- 仅一条保留：在相同中心线上以普通直波导补齐该段，不能留下四臂crossing或仍把它计为交叉。
- 两条都删除：不放置该单元。

仅导出可达的几何层级，不通过引用未裁剪母单元掩盖多余波导。将直线/圆弧连续合并，保留原20 µm半径与crossing footprint，不以相邻交换链作为全片默认后端。局部避让如需额外转弯或crossing，必须单独记录原因并纳入全片统计。

西侧输入保持前N条轨道顺序；东侧O是有序子集，使用不交叉、顺序保持的端口适配压缩为N个外部口。适配曲线通过半径及净距验收，不能只做标签重命名。层级图必须显式区分外部接口、有效边、终端支路，未被选中的母网端口不形成外部waveguide stub。

逐列器件间若有因稀疏轨道造成的间隙，保留实际坐标并允许后续确定性局部压缩，但不得改变原相对顺序或隐匿I/O交叉。是否压缩以全片几何为依据，不作为首次逻辑构造的前提。

### 5. 56个片内终端是需要实现的几何

所有保留 MZI仍使用完整2×2光学本体，缺少有效边的输入/输出端接入独立的定向终端。绑定键为 `(switch_id, physical_pin)`，不能仅按轨道号统计；100路固定28+28。

复用终端占位接口，保持 `reflectionless=False` 等真实性标识，提供足够的定向直线/必要圆弧引线及光学/金属禁布区。优先在已裁去支路释放的区域安排终端，必要时增大局部级间间隔；终端体、引线和由其产生的避让全部进入包络和crossing计数。

现有终端仅用于母网外侧闲置光口，不能原样套用其“西/东边界spare”验证。新验证从所有保留器件端口重建归属，检查四个端口恰好各有一个连接对象，并核对终端朝向、实际端点、多边形连续和净距。硬约束不满足时拒绝候选，不能取消终端或声称终端不影响有效路径因而免检。

### 6. 共享G、电学逃逸和408个pad

复用 `as_geometry.variants` 的光学本体与左右电学变体，沿用单MZI独立S via及列级G所有权。根据实际相邻器件、光学支路和终端的禁布区计算可共享G连续段；每条允许共享的G轨一个接触及via，被光学阻隔时分段，再接公共G。接点/via数量由几何导出，不沿用AS参考710个G接点或2528个via。

参考的400个开关按物理y/列稳定排序平衡分给南北各200个S；每侧4个G pad，占用两排共204个位置，每排102个。保持60 µm pad、至少100 µm同排中心距、至少70 µm行距和直接M2 pad末端。按源干线顺序排布pad，保留外排穿越内排空隙所需的净距；默认采用既有routing分布，不要求所有局部横向错位恰好50 µm。

固定格点下pad跨度估算为 `101*100 + 50 + 60 = 10210 µm`，仅供初始预算，不是芯片宽度结论。实际网络为400个S+1个G，8个G pad均为同一网络；终端附近不放宽M1或via的光学禁布规则，M2仅按原绝缘跨越合约处理。

小规模时按可用列数限制G tap数量，S数奇偶引起的银行差不超过1；不强制小规模也具有每排102个pad。100路参考保留全部8个G pad。

### 7. 有界候选与验收顺序

复用AS候选的有界搜索思路，在34/35 µm各评估7列的128种左右引出组合的低成本估算；每个间距挑选最多8个完整几何候选，并保留1个全右出控制组，合计最多18个完整候选。相同方向在不同pad相位中的低成本比较先择优，不无限扩大全片生成数量。

硬过滤顺序：拓扑/请求正确 → 几何与电学通过 → 实际全片crossing<4522。通过后按面积、宽度、实际crossing、S转折、线长、路径差异、稳定ID择优。面积依据所有光学、金属、终端、pad及边缘的实际包络。报告软宽度目标20 mm和相对现有92.253366908632 mm²的差异；不要求降低面积作为隐含的可用性条件，但若面积增加必须显著说明。

2433是原顺序核心的计数目标，不是提前锁定的最终GDS实例总数。没有通过硬约束的候选就返回失败并保留淘汰原因，不将图通过当成交付完成，不自行扩大搜索、改变器件或恢复448-MZI母网。

### 8. 验证和交付结构

三个验收层次：

1. **逻辑**：N=2…8全部置换与独立判定对照；N=100全部10,000对单连接、全bar满载映射、固定种子17的100组满载参考子集和100个随机完整请求，分别核对成功或阻塞。小规模枚举完整开关状态形成可路由置换集合可作为独立oracle，不能共用求解器的冲突判断。另以唯一路径动态计数验证裁剪前后关系，测试删边及错接。
2. **几何**：小规模5/7/12/13路覆盖稀疏列与终端，34/35 µm及左右出线按代表用例检查；器件几何、每条边、所有端口归属、两路crossing、终端及电学禁布规则均校验。注入开路、短路、错误crossing、非法半径、错终端、via和pad间距故障。
3. **GDS与复现**：独立读回层级/多边形/连接，抽取401个电学网络，核对400 MZI、56终端、408 pad与200个外部光口；全片实际crossing与manifest/报告交叉核对。重复生成选定候选两次，比对去除时间戳后的几何、拓扑、状态及指标，再跑历史回归。

新包沿用现有可审查形式：config/network/manifest/settings/report、端口/终端/pad映射、GDS和cell names、允许的M2跨越窗口、候选选择/淘汰记录、总览以及端口压缩、内部终端、共享地和pad局部图。路径统计区分请求路径与拓扑全部可达路径，固定7个MZI不等于长度或损耗相等。

## Risks / Trade-offs

- [裁剪端口选择错误导致满载能力丢失] → 固定上述匹配选择规则，单独验证全bar100路同时配置；保留“两端前100口最多79路”的反例测试，不将其作为默认候选。
- [2433个图交叉不等于可制造的2433个交叉] → 分别统计核心、适配、终端附加交叉；全部几何验收通过且实际总数少于4522才交付。
- [稀疏模板错误地保留crossing残臂或删除有效边] → 按每条实际轨迹重建层级与端口图，对单边保留crossing替换做专门故障测试。
- [128轨道局部高度及终端使面积反增] → 真实包络择优，终端/适配不从面积中排除；报告比较而不提前宣称尺寸改善。
- [阻塞网络被旧完整置换契约误判] → 独立的状态/暗输入/终端语义，CLI显式参考映射，失败状态与旧包分离。
- [终端反射及未请求输入的漏光] → 只交付几何占位终端，公开性能未验证；未请求输入保持暗态，活动路径禁止进入终端，后续器件校准不包含在本次验收中。
- [复用电学代码使旧模式退化] → 新模式独立分派，抽取共享辅助时保留原输出契约及回归覆盖。

## Migration Plan

先接入新配置/显式图/求解与CLI，再实现稀疏连续光学和终端，然后复用共享地与pad生成完整小规模布局，最后生成100路候选并独立读回、复现和对比。新示例为 `examples/benes/pruned-banyan/n100.json`，输出为 `output/benes/pruned-banyan/n100/`，说明建议放在 `docs/PRUNED_BANYAN.md`。

保留全部历史配置和示例，不修改默认拓扑。回退时选择原 `exact100-balanced/regular.json` 及其固定choice即可。此次规划文件齐备后再按apply工作流实施；所有任务在实现及相应验收完成前保持未勾选。

## Open Questions

- 34或35 µm、各列左右电学引出及局部间隔的最终值，由上述18候选上限内的几何验收决定。
- 终端与东侧顺序保持适配的最小可行占地，由小规模及100路几何检查决定；允许调整局部间距和走线，不允许改变终端数量、端口选择或固定器件约束。若全部候选都无法满足硬约束，作为实施阻碍报告，不能静默缩减规格。
