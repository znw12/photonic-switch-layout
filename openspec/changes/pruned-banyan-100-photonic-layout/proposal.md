# Proposal

## Why

当前精确100路 AS-Beneš 参考包含596个 MZI 和4,522个 crossing。用户已接受单平面内部阻塞，并允许内部局部扩展至128条通道，希望在保持100个外部输入/输出和现有光电器件约束的同时，减少 MZI 与实际物理交叉。

## What Changes

- 新增显式 `pruned-banyan` 拓扑。100路参考从128路、7级递归 Banyan 中选择相互匹配的100个输入/输出，按全部有效路径的并集裁剪，保留400个 MZI；每个有效输入—输出对只有一条路径，均经过7个 MZI。
- 保留至少一种同时100路的一对一连接配置；对其他单连接、部分连接和完整请求执行确定性的路径/开关状态冲突检查。接受阻塞，明确拒绝冲突，不继续承诺任意100路置换或静默分时完成。
- 外部严格100输入/100输出；内部级间有效通道数为100、100、104、112、128、128。28个未用 MZI 输入端及28个未用输出端在片内显式处理，不增加外部光口、不保留整个未裁剪128路内核。
- 保持1 mm MZI、680 µm 有源电极、GSG、至少20 µm弯曲半径、20×20 µm cosine crossing、M1/M2与via、共享地、单带西入东出，以及南北各两排60 µm pad和同排至少100 µm中心距。参考包含400个独立信号pad与8个共地pad。
- 用连续光学布线实现裁剪图，联合选择34/35 µm端口间距、逐列电学引出方向和按引线排布的pad。2,433是保持原相对轨道顺序的级间图计数；实际交付必须统计全部交叉，包括端口适配和终端避让，并少于当前4,522个。面积优先择优，20 mm宽度仍为软目标，尚不承诺已取得尺寸改善。
- 新增独立示例、输出、CLI路由行为、验证和对比报告；保留原 Beneš/AS-Beneš 模式、默认行为、配置哈希及历史示例。

## Capabilities

### New Capabilities

- `pruned-banyan-network`: 匹配端口裁剪、稳定端口映射、唯一路径、满载参考配置、阻塞诊断和独立走图验证。
- `pruned-banyan-physical-layout`: 稀疏列与级间布线、片内终端、GSG共享地、两排pad，以及保持原器件约束的参数化层级布局。
- `pruned-banyan-verification-delivery`: 全部单连接与冲突验收、GDS独立读回、故障注入、全片指标、复现和历史模式兼容。

### Modified Capabilities

无。当前主规格目录没有已发布能力；本次新模式使用独立规格，不改写历史 AS-Beneš 对无阻塞和内部精确规模的要求。用户确认的阻塞与内部扩展仅适用于新模式。

## Impact

目标项目为当前 Python/gdsfactory/KLayout 布局工程，分支为 `codex/banyan-omega-topology`。涉及 `src/benes_layout/` 的配置、网络分派、CLI、几何、布局、指标及验证；复用现有器件与共享地/pad基础，新增裁剪网络和工作流。新增 `tests/` 测试、`examples/benes/pruned-banyan/n100.json` 和说明，生成包放入忽略的 `output/benes/pruned-banyan/n100/`。不计划新增生产依赖，也不把占位终端或几何验证描述为已验证的低反射、损耗或代工工艺性能。
