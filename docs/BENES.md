# Beneš 光子交换矩阵

最新单条带紧凑版为 **45.486 × 10.464 mm**，采用按级分组的四排错位 pad 和 60 μm 波导行距，见 [分组 pad 与行距优化](BENES_DISTRIBUTED_PADS.md)。

新增：南北 2/3 排 pad 和水平分带折叠见 [多排与折叠实验](BENES_RESHAPE.md)。下文保留原单排版本的数据作为基线。

独立的 gdsfactory 版图生成器：默认 100 个外部输入、100 个外部输出，完整 128×128 Beneš 内核，13 级、每级 64 个 TFLN MZI 占位单元，共 832 个。任何完整路径都经过 13 个 MZI；28 个备用输入和 28 个备用输出各自连接终止占位单元，没有裁剪内部开关或增加跳级旁路。

本版优先最小化 **包括焊盘、电学扇出、光接口、终止区和边界余量的整片面积**。在面积完全相同的候选间，依次比较路径长度差、交叉数量差、弯曲数量差、总布线长度。等开关级数是硬约束；不默认以扩大芯片为代价追求等长，也不把等开关级数当成等损耗。

## 运行

使用项目已有 `.venv` 和 `requirements.lock`。增加 CLI 后需要刷新一次本地安装：

```bash
.venv/bin/python -m pip install --no-build-isolation --no-deps -e .
.venv/bin/benes-layout generate --config examples/benes/n100.json --out output/benes/n100 --connections identity
.venv/bin/benes-layout verify output/benes/n100

# 单连接或部分并发连接，外部端口编号均为 0–99
.venv/bin/benes-layout solve --n 100 --connections 0:73,1:4 --out output/benes/settings.json
.venv/bin/benes-layout generate --n 4 --out output/benes/n4
.venv/bin/benes-layout generate --n 5 --out output/benes/n5
.venv/bin/benes-layout generate --n 16 --out output/benes/n16
.venv/bin/benes-layout benchmark --sizes 16,128,256,1024 --out output/benes/scaling.json
.venv/bin/python -m benes_layout.validation --out output/benes/functional.json
.venv/bin/python -m pytest -q
```

在当前受限环境中可为生成、回读和测试命令设置 `MPLCONFIGDIR=/tmp/benes-mpl`。图像使用无图形界面的 Agg 渲染器。`solve` 与拓扑基准不加载 gdsfactory。

连接参数支持 `identity`、`reverse`、`none`、`0:73,1:4` 或包含输入/输出编号对的 JSON 文件。不同连接不能重复占用同一个输入或输出。未请求的内部连接会被确定性补全；MZI 不是遮光器，单连接工作时其余输入需要保持无光。网络支持同时 100 条一对一连接，但重配置可能影响正在使用的路径，不保证无中断。

`--n` 设置外部端口数；`--internal` 可显式指定不小于外部端口数的二次幂内核。默认取最小可容纳内核，且至少为 2。例如 5 个外部端口使用 8 端口内核，1 个外部端口使用 2 端口内核。

## 五项要求的实现

| 要求 | 实现与验收 |
|---|---|
| Parameterization | 独立 `Config`；配置外部/内部端口、两侧映射、MZI 尺寸/端口、半径、金属/via、焊盘、终止单元、层、搜索范围；输出完整解析配置 |
| Hierarchy | CHIP → FABRIC → STAGE → MZI；独立 INTERSTAGE → SPLIT/MERGE → EXCHANGE → BEND/CROSSING；另有光接口、终止、金属和焊盘层次 |
| Routing strategy | Beneš 专用、解析生成的重复 shuffle/unshuffle 模块；紧凑 M2 干线与阵列外 M1 扇出；显式 crossing 和 via |
| Scalability | 逻辑图和求解器支持任意二次幂内核；完整验证 4/4、5/8、16/16、100/128；另测量到 1024 端口的逻辑规模 |
| Verification | 独立逻辑遍历、精确路径极值、几何空间检查、GDS 多边形/实例回读、真实 M1/M2/VIA 导体提取、故障注入与重复生成 |

标准内核开关数为 `(P/2) × (2 log2(P) − 1)`。求解器使用递归输入/输出配对图染色；验证器直接遍历显式级间连接和开关状态，不使用求解器给出的“成功”标志作为证据。

新引擎没有调用 Waksman 拓扑、放置器或布线器。仅共享经检查的基础多边形、组件/GDS 导出和几何辅助函数，现有 Waksman 命令保持可用。

## 光电布线

MZI 沿 x 方向按级放置，光端口间距默认 80 μm，所有曲线中心线半径至少 20 μm。对 2m 个通道的完美洗牌，解析生成 m−1 列局部交换；反向列序实现逆洗牌。相同规模的重复子块共享 GDS 单元，无需对整个大网络进行通用排序布线。

每个局部交换由半径明确的圆弧和一个正交 crossing 占位单元构成，逻辑通道始终沿指定对穿端口传输。MZI 内部的耦合器是黑盒占位；报告采用配置的理想传播长度，不包含真实相位、耦合器或状态相关群延迟。

每个 MZI 有两个独立电极端口，各接自己的焊盘，不合并 return。832 个开关对应 **1,664 个焊盘**，南北各 832 个。每条电学连接包含局部 M1 引出、紧凑 M2 干线、阵列外 M1 展开及 M2 焊盘引线，三个显式 via 完成转换，共 **4,992 个 via**。

M2 仅在声明的直波导窗口绝缘跨越；窗口禁止 via，MZI、弯曲和 crossing 保持避让。该绝缘堆栈是占位工艺假设，不能直接用于投片。

## 当前默认结果

所有尺寸来自已通过几何检查与 GDS 回读的输出。使用同一器件、焊盘和工艺约束，搜索三个候选，选择结果如下：

| 外部 / 内部端口 | 级数 | MZI | 焊盘 | 完整尺寸（mm） |
|---|---:|---:|---:|---:|
| 4 / 4 | 3 | 6 | 12 | 3.925 × 0.988 |
| 5 / 8 | 5 | 20 | 40 | 7.013 × 1.364 |
| 16 / 16 | 7 | 56 | 112 | 11.021 × 2.116 |
| 100 / 128 | 13 | 832 | 1,664 | **87.560 × 12.644** |

100/128 示例整片面积约 **1,107.13 mm²**，相对于同约束的保守 Beneš 基线减少 **17.15%**。60 μm 方形焊盘、100 μm 间距下，单侧 832 个焊盘本身就需要至少 **83.16 mm** 横向跨度。当前 GDS 约 2.26 MB，包含 1,732 个不同单元和 28,833 个单元引用记录（不是扁平化实例总数）。

该结果是已评估可行候选中的最优值，不是全局最优证明。搜索优先变化级间余量、合法镜像行序、焊盘间距和电学干线间距；器件本身的接口不随候选改变。搜索预算、各候选结果和失败理由均写入报告。

### 均匀性边界

100/128 默认版图的全部有效单路径精确极值：

| 指标 | 最小 | 最大 |
|---|---:|---:|
| MZI 数量（含完整内核所有端口） | 13 | 13 |
| 几何路径长度（含活动 IO 和理想 MZI 长度） | 87.280 mm | 94.820 mm |
| 沿途 crossing 数量 | 0 | 240 |
| 沿途圆弧单元数量 | 0 | 480 |

全芯片包含 7,680 个 crossing。这些数字说明：完整 Beneš 保证开关级数相同，仍可能有明显的路径长度和交叉数量差异。当前优化按用户要求优先面积，未加入默认等长绕线。

报告用阶段有向无环图动态规划计算全部有效单路径的极值，并保存各自的证据路径。极值可以来自不同路径，不代表某个同时连接配置的统计分布。指定配置的每条路径、均值和总体标准差另列在 `realized`。弯曲数按圆弧单元数量计，同时报告累计绝对弯曲角。

可选 `equalize: true` 在已分配的输出直线区域增加圆弧绕线，针对当前请求配置改善长度差。它保持已选芯片外框，不改变开关拓扑，不声称匹配所有可能连接；空间不足时报告剩余长度差。默认关闭。

### 与现有 Waksman 示例比较

现有 Waksman 是精确 100 端口、573 个 MZI，单路径开关深度 4–13，整片约 89.098 × 8.240 mm。Beneš 使用 128 端口内核、832 个 MZI，深度固定 13；虽然这版宽度略小，但整片面积更大。这不是相同内部规模的直接优劣比较，也不构成损耗性能比较。

## 参数与替换器件

完整字段在 `src/benes_layout/config.py`。`input_map` / `output_map` 是外部编号到内部接口的独立单射；未被选中的接口自动终止。非法或重复映射会报错。参数变化会重新计算位置、布线和外框，逻辑开关标识保持稳定。

`build_layout(config, component_factory=...)` 支持在提供的组件库中注册替代 MZI、crossing 和终止单元。MZI 保留 `i0/i1/o0/o1`、配置声明的两电学端口、bar/cross 传输对、合法方向以及相应的传输长度记录；crossing 保留两组对穿端口；终止单元保留有方向的 `opt` 接口。工厂可从现有占位单元开始修改。接口校验在生成前执行，几何与物理检查在生成后执行。

更大的器件应通过配置改变外形和接口后重新布局。真实 TFLN 器件、crossing 性能、终止反射、电极驱动与金属堆栈尚未提供，需要通过这些接口替换并重新验证，当前检查不代替 foundry DRC 或光学/电学仿真。

## 输出与验证证据

输出目录包含 `layout.gds`、`preview.png`、`detail.png`、`config.json`、`network.json`、`settings.json`、`manifest.json`、`cell_names.json`、`pads.csv`、`ports.csv`、`report.json`。大体积生成文件位于忽略的 `output/`；可再生配置和代表性报告保存在 `examples/benes/`。

验证覆盖 2/4/8 内部端口的全部排列（共 40,346 种）、5/8 的非默认端口映射、100×100 的全部 10,000 个单连接，以及 100 活动端口和全部 128 内部端口的恒等、反序、循环移位与各 100 组随机排列。实际开关输出由独立遍历检查。100! 种并发组合没有被枚举。

最终测试共 **111 项通过**，包括保留的 Waksman 回归测试。两次完整 100/128、各三个候选的生成在规范化几何、开关设置、接口映射、候选选择和路径指标上完全一致，详细记录见 `examples/benes/reports/tests.json` 和 `reproducibility.json`。

物理验证同时检查实际端口连续性、未声明的相交、间距、解析圆弧、终止覆盖、完整层次与多边形、导体开路/短路、金属宽度和间距、via 包围及光电跨越窗口。故障测试会修改真实几何，并使 manifest 同步接受该修改，以确认检测依赖物理提取而不是只依赖文件哈希。

`verify` 重算图、几何、导体连接和路径统计，并与生成报告核对。失败候选记录原因；没有通过验证的保守基线时返回失败且不保留成功 GDS。不要在生成目录保存手工维护的文件。

拓扑基准分别记录构图、求解、验证耗时；Python 内存用每个规模单独的 `tracemalloc` 峰值，进程内存用 Linux `ru_maxrss` 高水位。1024 端口结果为 19 级、9,728 个开关，仅代表拓扑/求解能力，不代表已经完成 1024 端口的物理布线。
